# Security

## Reporting a vulnerability

Please report security issues privately through GitHub's
[private vulnerability reporting](https://github.com/krish-patel-01/legend-mode/security/advisories/new)
rather than opening a public issue.

This is a personal project, not a funded one — expect a best-effort response measured in
days, and no bounty.

## The threat model, stated plainly

**Legend Mode is designed to run on loopback, and it has no authentication.**

There is no API key, no rate limiting, no CORS policy and no request quota. Anything that
can reach the port can run inference, read whatever is in the retrieval corpus, and — if
the `notes` family is configured — write files into your Obsidian vault. This is a
reasonable design for a service bound to `127.0.0.1` on a laptop, and an unreasonable one
for anything else.

Accordingly:

- Every published port in `docker-compose.yml` is bound to `127.0.0.1` on purpose.
  Changing those to `0.0.0.0` publishes an unauthenticated LLM endpoint to your network.
- If you need remote access, put a reverse proxy in front that terminates TLS and
  authenticates. Do not widen the binding and hope.
- The SearXNG instance runs with its bot limiter disabled, which is only safe because it
  is loopback-only. See `deploy/searxng/settings.yml.example`.

Reports that amount to "the unauthenticated endpoint is unauthenticated" are documented
behaviour rather than vulnerabilities. Reports that it is *reachable* when it should not
be — a binding that escapes loopback, a path that leaks the corpus or vault, a container
that runs as root — are real, and worth sending.

## Secrets

Nothing secret should ever be committed:

- `.env` is gitignored and has never been tracked. `.env.example` documents the settings
  with no values.
- `deploy/searxng/settings.yml` is gitignored and generated by `deploy/searxng/up.sh`,
  which mints a fresh secret key locally. Only the template is committed.
- `.dockerignore` excludes `.env`, so it cannot be baked into an image by accident.

## What a model can be talked into

Two behaviours worth understanding before trusting output, both measured rather than
assumed:

- **Retrieved text can override correct knowledge.** Injecting a merely-plausible passage
  is how retrieval makes answers worse rather than better, which is why the similarity
  cut-off sits well above the naive midpoint. Anything you ingest into the corpus is
  something the model will believe.
- **The small tier cannot verify anything.** The 350M scored at chance as a critic and
  rubber-stamped 8 of 8 wrong answers. Do not build a check on top of it, and do not read
  a passing answer as a verified one. See `docs/measurements.md`.

## Dependencies

`uv.lock` pins the full dependency tree, and CI installs with `--frozen`. Dependency
updates are manual; there is no automated bot on this repository yet.
